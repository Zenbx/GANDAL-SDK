# GANDAL SDK v0.6.0

**Date :** 2026-11-16 · **Version précédente :** v0.5.0 · **Type :** mineure, avec changements incompatibles (version 0.x)

## Résumé

Cette version rend le SDK utilisable contre le vrai backend : les identifiants
de demandes et de profils suivent enfin le contrat (chaînes UUID), trois helpers
orchestration manquants arrivent, et deux briques IAM côté client - `GardeIam`
(séquence de quota) et `AccesSsh` / `gandal-ssh` (entrée VM) - ferment la boucle
ouverte en 0.5.0.

## Changements incompatibles et migration

| Changement | Avant | Après | Action requise |
| --- | --- | --- | --- |
| `RequestOut.id` et `request_id` | `int` | `str` (UUID) | typer / stocker l'id en chaîne ; le dépôt de demande ne lève plus |
| `ProfileOut.id` et `profile_id` | `int` | `str` | remplacer les entiers par les UUID renvoyés par l'API |
| Schémas de contrat profils | `ProfileCreate`, `ProfileUpdate`, `PaginatedProfilesOut` | `ProfileCreateIn`, `ProfileUpdateIn`, `Page_ProfileOut_` | uniquement si un outil lit les noms OpenAPI du test |

Sans migration, tout code qui suppose un `id` numérique de demande ou de profil
casse à la validation Pydantic ou à l'appel HTTP.

## Nouveautés

**Garde IAM côté client.** `GardeIam` enchaîne décider → réserver → confirmer,
et libère la réservation si le corps lève. Ce n'est pas le contrôle d'accès
(autorité = backend) ; c'est la comptabilité des quotas et un refus tôt.

```python
from gandal_sdk import GandalClient, GardeIam

client = GandalClient.from_env()
with GardeIam(client.iam, sujet="etu-1", projet="p-vision") as g:
    g.autoriser_creation("poste-1", vcpu=2, ram_gb=4, disk_gb=20)
    demande = client.orchestration.vms.request_create(projet, corps)
    g.confirmer(demande.vm_id, "vm")
```

**Resize IAM.** `IamCell.resize_resource(resource_id, quantites)` prend des
quantités **absolues**. `GardeIam.autoriser_modification` s'en sert pour que
`vm:update` compte l'écart, pas une double taille.

**Accès SSH.** `AccesSsh` demande un certificat éphémère au signeur ; la CLI
`gandal-ssh` ouvre la session. Clé de session, détruite à la sortie du
contexte - rien ne s'accumule dans `~/.ssh`.

```bash
gandal-ssh poste-vision-01
```

**Helpers orchestration.** `auth.register(body)` (jeton posé comme `login`),
`health.ready()` (`GET /ready`, hors `/api/v1`), `profiles.create_admin(body)`
(identité, pas de jeton).

**Contrats.** Instantané `openapi/iaas-api.json` : 6 → 46 routes ; modèles
`RegisterIn`, `ReadinessOut` sous contrôle de contrat.

## Corrections

- Pydantic levait à chaque dépôt de demande : `RequestOut.id` était déclaré
  `int` alors que le backend rend un UUID.
- `ProfileOut.id` / `profile_id` alignés sur `String(36)` du backend.
- Le détecteur de couverture ne marque plus à tort les routes `.../deletion`
  servies via `delete_two_step`.
